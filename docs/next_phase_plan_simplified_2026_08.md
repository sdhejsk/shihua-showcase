# 平台后续建设计划

## 总体思路

后续平台建设工作主要围绕以下三个点展开：

1. 系统形态与界面风格还不像中石化已有业务系统，需要调整成更正式、更业务化的平台。
2. 数据规模和覆盖范围还需要继续扩大，尤其要从当前局部区域扩展到更多海外区域。
3. 需要研究和借鉴旧平台的业务流程，把它的项目管理、评价协同和任务推进方式转化到我们的系统中。

因此，下一阶段计划可以概括为：以旧平台为参照，以海外油气数据接入为基础，以项目评价业务流程为主线，推动当前原型系统向正式业务平台升级。

## 一、系统风格与平台形态优化

### 目标

当前系统已经具备数据展示、MapGIS 服务接入、空间浏览、井资料查看和评价算法原型等功能，但整体观感仍更像一个数据展示原型，和首席提供的旧平台风格存在差异。

下一步需要把系统从“演示页面”调整为“中石化风格的海外油气项目快速评价协同工作平台”。

### 重点任务

1. 对标旧平台界面风格

重点参考旧平台的顶部菜单、业务模块命名、表格布局、筛选条件、任务列表、项目状态区等设计方式。

需要把当前系统中过于互联网化、卡片化、说明性过强的界面，调整为更偏业务系统、管理系统和生产系统的风格。

2. 重新组织首页和模块入口

首页不再只展示数据概览，而应突出平台的核心业务入口，例如：

- 项目运行情况
- 待办任务列表
- 数据资源管理
- 快速评价
- 指标体系
- 标准规范
- 成果报告

3. 优化数据模块页面

数据模块需要更加清晰地展示盆地、区块、油气田、井位和资料数据。当前“所有信息堆在页面里”的方式需要继续优化，改成更清楚的列表、筛选、详情、地图联动方式。

4. 统一页面风格

统一字体、颜色、按钮、表格、查询框、分页、弹窗、详情页样式，让系统看起来像一个完整平台，而不是多个功能页面拼在一起。

### 阶段成果

- 完成一版中石化业务系统风格的界面改造方案。
- 完成首页、数据模块、地图模块、评价模块、服务状态模块的统一风格优化。
- 形成“旧平台风格对标清单”，明确哪些地方已经参考，哪些地方后续继续改。

## 二、海外数据继续扩展与规范化接入

### 目标

目前系统已经接入了盆地、合同区块、油气田、井位、井资料、部分 Excel 表格、PDF 文档以及 MapGIS IGServer 发布的空间服务。后续需要继续扩大数据覆盖范围，尽量从单一区域扩展到更多海外区域，形成更完整的海外油气数据底座。

### 重点任务

1. 梳理现有数据

对当前已经掌握的数据进行统一盘点，明确：

- 哪些是 GIS 空间数据
- 哪些是 Excel 表格数据
- 哪些是 PDF 或文档资料
- 哪些数据已经接入系统
- 哪些数据只是下载到了本地但还未接入
- 哪些数据已经通过 MapGIS IGServer 发布
- 哪些数据只是前端或 Node 后端直接读取

2. 扩展海外区域数据

当前已经尝试接入非洲相关数据，后续可以继续按区域扩展，例如：

- 非洲
- 中东
- 中亚
- 东南亚
- 南美
- 欧洲及周边

扩展时不只是简单“多加数据”，而是尽量围绕一个区域形成完整的数据组合：

- 盆地
- 区块
- 油气田
- 井位
- 井资料
- 合同信息
- 相关报告或 PDF 文档

3. 规范 GIS 数据接入流程

GIS 类型数据原则上优先通过 MapGIS IGServer 发布为 FeatureServer 服务，再由前端调用。

后续需要形成固定流程：

- 从标普或其他来源下载 Shapefile
- 检查坐标系和字段
- 放入统一数据目录
- 通过 MapGIS IGServer 发布服务
- 在系统配置中登记服务名称、图层 ID 和字段
- 前端通过统一接口读取并展示

4. 规范表格和文档数据接入流程

Excel、CSV、PDF 等非空间数据也需要统一管理，不能每次临时写死。

后续需要形成：

- 数据目录规范
- 文件命名规范
- 字段映射规范
- JSON 转换规范
- 数据来源和更新时间记录
- 数据与空间对象的关联规则

5. 推进数据库建设

当前项目还没有正式数据库，主要依赖文件、JSON、Excel 和 MapGIS 服务接口。后续如果数据继续增多，必须考虑建设数据库。

建议后续把数据库建设列为重点工作，优先考虑：

- PostgreSQL
- PostGIS
- 空间数据表
- 业务属性表
- 项目评价表
- 文件资料索引表
- 数据更新记录表

### 阶段成果

- 形成海外油气数据接入清单。
- 完成更多海外区域的数据接入。
- 形成 GIS 数据和表格数据的标准接入流程。
- 形成数据库建设初步方案。

## 三、借鉴旧平台业务流程，形成评价协同闭环

### 目标

旧平台的价值不只在界面，而在它背后的业务流程。我们后续需要重点研究旧平台如何组织项目、任务、评价、指标、标准和成果，并把可借鉴的流程吸收到当前系统中。

### 重点任务

1. 调研旧平台功能流程

等旧平台恢复访问后，需要重点查看：

- 项目登记与管理
- 项目运行状态
- 待办任务列表
- 指标体系管理
- 快速评价方法库
- 标准及规范查询
- 标准及规范值管理
- 项目评价流程
- 评价成果输出
- 用户角色和权限

如果条件允许，应进一步争取：

- 旧平台源码
- 数据库结构
- 数据字典
- 测试账号
- 典型项目样例
- 评价方法说明文档

2. 提炼可借鉴流程

不能只是照着旧平台做页面，而是要提炼它的业务逻辑。例如：

- 一个项目从登记到评价完成，需要经历哪些步骤
- 每个步骤需要哪些数据
- 谁负责填写、审核或推进
- 哪些数据来自系统自动读取
- 哪些内容需要人工录入
- 最终输出什么成果

3. 转化为我们自己的系统流程

建议把后续平台流程设计为：

- 数据接入
- 区域或项目选择
- 项目基础信息登记
- 盆地、区块、油气田、井资料联动查看
- 评价指标选择
- 评价参数输入
- 算法计算
- 结果解释
- 报告生成
- 任务状态流转

4. 完善评价算法模块

当前评价算法模块还只是原型，后续应重点调整为“可输入参数、可调整权重、可解释结果”的业务工具，而不是只展示固定结果。

后续需要逐步建立：

- 指标体系
- 评价方法库
- 参数输入表单
- 权重配置
- 结果计算
- 结果解释
- 项目对比
- 报告输出

### 阶段成果

- 形成旧平台业务流程调研报告。
- 形成我们系统的项目评价流程图。
- 完成一版“项目登记-资料查看-参数输入-评价计算-结果输出”的闭环原型。
- 明确哪些流程直接借鉴旧平台，哪些流程结合我们自己的数据重新设计。

## 近期推进顺序

### 第一阶段：先看清旧平台

时间建议：1 周。

主要任务：

- 等旧平台恢复访问后，完整梳理旧平台功能。
- 截图记录关键页面和流程。
- 列出旧平台值得借鉴的功能。
- 明确我们当前系统和旧平台的差距。

输出成果：

- 旧平台功能清单
- 旧平台流程梳理
- 当前系统差距清单

### 第二阶段：先改系统形态

时间建议：1 到 2 周。

主要任务：

- 调整首页和导航结构。
- 优化界面风格，使其更接近正式业务系统。
- 优化数据模块、地图模块、评价模块的页面组织。
- 减少说明性文字，强化功能入口和业务状态。

输出成果：

- 新版平台首页
- 新版模块导航
- 新版数据和评价页面

### 第三阶段：继续扩展海外数据

时间建议：2 到 4 周。

主要任务：

- 按区域继续接入更多海外数据。
- 统一 GIS 服务发布和表格数据整理流程。
- 保留已有数据，不用新区域覆盖旧数据。
- 建立数据接入台账。

输出成果：

- 海外区域数据清单
- 多区域数据展示能力
- 数据接入规范

### 第四阶段：补齐业务闭环

时间建议：4 周以后持续推进。

主要任务：

- 建立项目管理流程。
- 完善评价算法参数输入。
- 建设指标体系和方法库。
- 规划数据库。
- 实现项目成果输出。

输出成果：

- 项目评价闭环原型
- 评价算法模块升级版
- 数据库建设方案
- 项目成果输出模板

## 需要协调的问题

后续推进过程中，需要尽快协调以下事项：

- 是否能获得旧平台长期访问权限。
- 是否能拿到旧平台源码或数据库结构。
- 是否能拿到旧平台的数据字典和评价方法说明。
- 是否明确平台最终要对标旧平台到什么程度。
- 是否确定优先扩展哪些海外区域。
- 是否允许建设正式数据库。
- 是否确定 MapGIS IGServer 作为空间服务发布的主要标准。
- 是否需要和其他专题组共同确定评价指标和算法依据。

## 简要总结

下一阶段工作主要围绕三件事推进：第一，把系统界面和平台形态调整得更像正式的中石化业务系统；第二，继续扩大海外油气数据接入范围，形成更完整的数据底座；第三，研究旧平台的项目评价流程，把可借鉴的流程转化成我们自己的项目管理和快速评价闭环。
